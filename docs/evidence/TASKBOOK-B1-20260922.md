## 4. 过程中发现并修正的一处工具陷阱

用 Python 脚本批量改这三个文件时，`Path.write_text` 在 Windows 上把 `\n` 翻译成了 `\r\n`，
导致 biome 报 3 处 format 错误（工作区 CRLF）。仓库 `.gitattributes` 的 `* text=auto eol=lf`
只在**提交时**归一化 blob，工作区不受约束——所以本地会红、CI 反而可能绿。
改用二进制读写（`read_bytes` / `write_bytes`）后消除。后续同类批量编辑务必走二进制路径。

（同源事故的另一面：viral 分支的迁移守卫曾因**提交前**工作区 CRLF 而把 CRLF 字节的 sha256 记进
`manifest.json`，CI 检出 LF 后 sha 不匹配 → 已在 PR #205 的 `0b95e2f3` 修正。）
