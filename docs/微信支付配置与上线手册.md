## 0. 一页速查

配置分三层，**缺任何一层都收不到钱**：

| 层 | 在哪里配 | 谁来配 |
| --- | --- | --- |
| 微信支付商户平台 | pay.weixin.qq.com | 运营（需商户管理员权限） |
| 服务端环境变量 | `/etc/video-replica/customer.env` | 运维（改完需重启 API） |
| 管理后台 | 管理台 → 支付设置 | 运营 |

上线前最小检查清单：

```text
□ 1. 商户平台已开通 Native 支付、已下载 API 证书、已设置 APIv3 密钥、已绑定 AppID
□ 2. customer.env 中 PUBLIC_BASE_URL == VIDEO_REPLICA_PUBLIC_ORIGIN，HTTPS 443 公网可达
□ 3. 管理台填齐 5 个商户字段
□ 4. 点「凭据自检」→ 必须提示通过
□ 5. 计费参数（最低充值 / 充值步长 / 积分兑换比例）已设置
□ 6. 「默认充值通道」切到「微信官方（Native）」
□ 7. 真机小额实付一笔，确认到账 + 管理台订单页能看到微信交易单号
```

## 1. 微信支付商户平台准备

在填我们后台之前，先在微信商户平台拿到四样东西：

| 准备项 | 说明 |
| --- | --- |
| **开通 Native 支付** | 产品中心开通「Native 支付」。未开通时下单会收到 `NOAUTH` |
| **API 证书** | 「账户中心 → API 安全」申请，下载得到 `apiclient_key.pem`（商户私钥）与**证书序列号** |
| **APIv3 密钥** | 「账户中心 → API 安全」自行设置的 32 位字符串。**只在设置时可见，务必自行留存** |
| **绑定 AppID** | 商户号需与公众号 / 小程序 / 开放平台应用完成关联 |

> **回调地址不需要在商户平台配置。** Native V3 的 `notify_url` 是随每次下单请求传给微信的，由服务端从 `PUBLIC_BASE_URL` 推导。商户平台上只需保证域名可公网访问。

## 2. 服务端环境变量

文件：`/etc/video-replica/customer.env`（示例见 `deploy/customer.env.example`）

| 变量 | 示例 | 约束 |
| --- | --- | --- |
| `VIDEO_REPLICA_PUBLIC_ORIGIN` | `https://video.example.com` | 对外唯一 HTTPS origin |
| `PUBLIC_BASE_URL` | `https://video.example.com` | **必须与上一项逐字相同** |
| `VIDEO_REPLICA_TRUSTED_PROXY_CIDRS` | `127.0.0.1/32,::1/128,172.30.42.1/32` | Nginx 对端 CIDR，回调要穿过这道边界 |

`PUBLIC_BASE_URL` 的格式校验很严，以下任何一条不满足都会让支付整体不可用：

- 必须是 `https`（`http` 直接拒绝）
- 必须是**纯 origin**：不能带路径、query、fragment，不能带用户名密码
- 应使用标准 443 端口（微信只接受 80/443 的回调地址）

回调地址由它推导，不可单独配置：

```text
notify_url = {PUBLIC_BASE_URL}/api/payments/wechat_native/notify
```

客户生产模式（`VIDEO_REPLICA_CUSTOMER_PRODUCTION=true`）下，若 `PUBLIC_BASE_URL` 缺失或与
`VIDEO_REPLICA_PUBLIC_ORIGIN` 不一致，**服务会直接拒绝启动**并在日志中说明原因。

## 3. 管理后台配置

路径：管理台 → 支付设置。把「默认充值通道」切到「微信官方（Native）」后出现商户配置表单。

### 3.1 商户配置（5 项全部必填）

| 字段 | 对应微信侧 | 校验规则 |
| --- | --- | --- |
| AppID | 已绑定的 AppID | 非空 |
| 商户号（mchid） | 微信支付商户号 | 非空 |
| 商户证书序列号 | API 证书序列号 | 非空 |
| API v3 密钥 | APIv3 密钥 | **必须正好 32 字节** |
| 商户私钥（PEM） | `apiclient_key.pem` 全文 | 必须是可解析的 **RSA** 私钥（PKCS#8、未加密） |

使用要点：

- **密钥只写不读。** 保存后 API v3 密钥与商户私钥永远回显为 `********`。
  **留空 = 保留原值**，只有真填了新内容才会覆盖。AppID / 商户号 / 序列号会正常回显。
- 私钥请把 `-----BEGIN PRIVATE KEY-----` 到 `-----END PRIVATE KEY-----` **整段**粘贴进去。
- 五项缺任意一项，保存时报「商户配置不完整」，切换默认通道也会被拒。

### 3.2 计费参数

不设置这些参数客户无法发起充值：

| 参数 | 约束 |
| --- | --- |
| 最低充值金额 | ≥ 100 元（10000 分），且必须能被充值步长整除 |
| 充值步长 | ≥ 10 元（1000 分），且必须能被单价整除 |
| 积分兑换比例（`points_per_yuan`） | ≥ 1，即 1 元兑多少积分 |

### 3.3 默认充值通道

切换到「微信官方（Native）」后**只对新订单生效**，存量订单继续按下单时的通道走完自己的生命周期。
切换前系统会校验所选通道的商户配置是否完整，不完整则拒绝切换。

## 4. 凭据自检（强烈建议每次改配置后执行）

管理台支付设置页有「凭据自检」按钮，对应接口：

```text
POST /api/control/settings/customer-payments/wechat-native/self-check
```

它会用已保存的凭据**真的向微信请求一次平台证书**，一次性验证三件事：

1. 商户号 + 证书序列号 + 商户私钥的签名能被微信接受
2. APIv3 密钥能解密微信返回的证书
3. 商户配置本身完整

只读操作，不保存任何东西，也不污染证书缓存。

> **为什么必须点。** 保存配置时只做本地格式校验（PEM 能否解析、密钥是否 32 字节），
> 不会验证这些凭据在微信那边是否真的匹配。不做自检的话，配错要等**第一个真实客户下单**才暴露。

通过时提示：`商户凭据有效：签名被微信接受，平台证书解密成功。`

## 5. 上线验证

配置齐全后，用真机小额实付一笔走完整条链路：

| 步骤 | 预期 | 失败时看 |
| --- | --- | --- |
| 客户端发起充值 | 返回订单号，状态 PENDING | 计费参数是否设置 |
| 获取二维码 | 显示二维码，内容以 `weixin://` 开头 | 商户配置、`PUBLIC_BASE_URL` |
| 微信扫码支付 | 支付成功 | 商户平台是否开通 Native |
| 自动到账 | 前端 2 秒轮询后显示成功，积分入账 | **回调是否打通（见下）** |
| 管理台订单页 | 「支付通道」显示「微信官方」，「第三方单号」显示 `4200…` 开头的微信交易单号 | 同上 |

**最后一项是判断回调是否真的通了的关键。** 如果交易单号为空、订单仍停在待支付，
说明微信的回调没有打进来 —— 优先排查域名公网可达性、证书有效性、Nginx 转发头。

## 6. 运维须知

### 6.1 更换 AppID / 商户号有时间窗口限制

若存在处于**结算窗口**内的微信订单，修改 AppID 或商户号会被拒绝：

```text
结算窗口 = 支付窗口 2 小时 + 微信回调重推期 24 小时 = 26 小时
```

窗口内的订单仍可能通过用户支付、微信重推回调或兜底对账变成已支付，此时换商户身份会把它们甩在旧身份上。
等窗口过去即可修改，**不要试图通过关单绕过**。

> 这个口径同时约束**商户身份变更**与**积分转换**两处判据，调整时必须两处同步改，
> 只改一处会出现「锁放宽了但转换还拦着」的不一致。

### 6.2 服务器时钟必须校准

回调校验带有 **±5 分钟**的时间戳新鲜度门，且在下载平台证书**之前**就拦截。

若线上突然出现**所有**微信回调都报 `WECHAT_CALLBACK_STALE_TIMESTAMP`，
**先查服务器 NTP 校时**，不要放宽阈值 —— 放宽阈值等于重新打开重放攻击窗口。

### 6.3 定时任务

两个微信相关的维护任务挂在 `video-replica-maintenance.timer` 上，当前频率为**每天 04:10 一次**：

| 任务 | 作用 |
| --- | --- |
| `scripts.reconcile_pending_native_orders` | 掉单兜底：主动向微信查询超过 10 分钟仍待支付的订单，已支付则补入账 |
| `scripts.close_expired_native_orders` | 把超过 2 小时支付窗口仍未支付的订单置为已关闭 |

两个任务都支持 `--dry-run` 只读查看待处理量：

```bash
cd /opt/video-replica/app/server
.venv/bin/python -m scripts.reconcile_pending_native_orders --dry-run
.venv/bin/python -m scripts.close_expired_native_orders --dry-run
```

> **注意频率。** 兜底对账一天只跑一次，意味着回调链路整体故障时，已付款客户最坏要等约 24 小时才被自动补单。
> 微信自身会在 24 小时内重推通知，所以回调仍是主路径。若要缩短兜底延迟，
> 建议为这一项单独配置 15–30 分钟的 timer，而不是调高主维护 timer 的频率（其上还挂着清理类任务）。

### 6.4 关单不等于拒付

被清扫任务关闭（CLOSED）的订单**仍然接受迟到的回调并正常入账**。
关单只是让无法再支付的订单达到终态，不影响资金。

## 7. 故障定位

### 7.1 回调错误码

回调被拒时日志会记录具体错误码：

| 错误码 | 含义 | 处置 |
| --- | --- | --- |
| `WECHAT_CALLBACK_MISSING_HEADERS` | 缺少微信验签头 | 检查是否有中间层剥离了 `Wechatpay-*` 头 |
| `WECHAT_CALLBACK_SIGNATURE_INVALID` | 验签失败 | 请求体被中间层改写，或确为伪造 |
| `WECHAT_CALLBACK_STALE_TIMESTAMP` | 时间戳超出 ±5 分钟 | **查 NTP 校时**（见 6.2） |
| `WECHAT_CALLBACK_CERT_UNAVAILABLE` | 拿不到平台证书 | 出网受限或被微信限流，可重试 |
| `WECHAT_CALLBACK_DECRYPT_FAILED` | APIv3 密钥解不开 | 后台填的密钥与商户平台不一致 |
| `WECHAT_CALLBACK_MERCHANT_MISMATCH` | 回调里的 mchid / appid 与后台配置不符 | 多见于刚换过商户身份、旧商户的回调仍在重推；也可能是配置串号 |
| `WECHAT_CALLBACK_CONFIG_INVALID` | 商户配置不完整 | 回后台补齐五项 |
| `WECHAT_CALLBACK_PAYLOAD_INVALID` | 内容真实但缺结算字段 | 记录并联系微信技术支持 |

### 7.2 下单 / 查单失败

调用微信接口失败时，日志会带上微信返回的 `code` 与 `message`，常见的：

| 微信 code | 常见原因 |
| --- | --- |
| `SIGN_ERROR` | 证书序列号与商户私钥不匹配 |
| `NOAUTH` | 商户未开通 Native 支付 |
| `PARAM_ERROR` | 参数不合法，多为回调地址格式问题 |
| `ORDERPAID` | 订单已支付（幂等场景，通常无需处理） |

出现前三种时，**先点一次「凭据自检」**即可快速定位是不是凭据问题。

### 7.3 常见现象速查

| 现象 | 最可能的原因 |
| --- | --- |
| 客户扫码后一直转圈，订单停在待支付 | 回调打不进来：域名不可达 / 证书问题 / Nginx 转发头不对 |
| 提示「支付二维码暂时无法生成」 | 商户配置错误或微信接口异常，看日志里的微信 code |
| 提示「该充值订单已超过支付时限」 | 订单已超过 2 小时支付窗口，属正常，让客户重新下单 |
| 管理台订单「第三方单号」为空 | 该订单从未成功回调入账 |
| 保存商户配置报「不能更换商户身份」 | 有订单处于 26 小时结算窗口内（见 6.1） |
