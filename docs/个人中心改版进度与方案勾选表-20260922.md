## 2.2 CI 回合（2026-09-22，PR #202）

本地门禁绿不等于 CI 绿。这一轮 CI 抓到两处，都记在这里：

| # | 现象 | 处置 |
| --- | --- | --- |
| 1 | `Linux quality gate` → `Run static quality checks` 在 `ruff format --check` 上 exit 1（`test_customer_account_security.py` 需重排两行） | **我方流程错误**：我跑了 `ruff format` 修它，但只在**工作区**改了、没有 commit。本地第二次 `check:sharded` 跑的是工作树（于是绿），推给 CI 的 `e34dd3a8` 仍是未格式化版本。已提交 `acc45975`。教训：门禁跑完后对工作树的任何改动都必须重新提交，否则「门禁保的是工作树、推的是旧提交」 |
| 2 | `Linux quality gate` → `Run customer browser E2E` 失败：`recharge.spec.mjs` 断言「已关闭」超时 | **真回归**（本批引入）：该用例用 `page.once("dialog", d => d.accept())` 等**原生** `window.confirm`；客户泳道 7 处已换成页内确认框，原生对话框不再出现，订单实际没被关闭。已改写用例显式驱动新确认框（勾选 + 确认），提交 `57e9c57a`；本机复跑整套客户 E2E 6/6 通过（33.5s） |

| 3 | 修完 E2E 后重推，`Run static quality checks` 又失败：`npm run check:e2e` 的 biome 报 `recharge.spec.mjs` 需重排 | 与第 1 条同类流程错误的**第二次**：改完 E2E 用例只跑了 Playwright（功能对），没跑 `check:e2e` 的 biome 门（格式不对）。已 `biome check --write e2e` 修，并且这次推送前把**完整** `npm run check:static` 与整套客户 E2E 都跑了一遍（6/6 通过）再推 |

**这三条的共同教训**（写下来免得再犯）：本地门禁只保护「跑它的那一刻的工作树」。任何在门禁之后做出的改动——哪怕只是格式——都必须重新跑**受影响的那道**门再推送。我前两次都是「跑完门禁又改了文件，只验证了改动的功能面」。

顺带确认：`e2e/customer/activation.spec.mjs` 有一条「personal center has … no device settings」的断言
（对应旧产品决定）。它是 web 端跑的，而 C 批的设备管理页签按 `devicePlatform() !== "browser"` 过滤，
因此在 web 端不出现，该断言不受影响——C 批合入时无需改它。

### 这一轮的两个教训

1. **「测试绿」可能是假绿**：第 5 条的回归锁第一版写成
   `new CustomerApiError({ message: "x", kind })`——该构造函数收的是 `transportKind`，传 `kind`
   会被忽略，getter 再从 status/code 推回 `unknown`，于是**遍历 18 种 kind 却全部命中兜底**，
   测试照样全绿。改用裸对象后才暴露。同理，`Record<string, …>` 换成
   `Record<Exclude<CustomerApiErrorKind, "unknown">, …>` 才能让「新增 kind 忘了补映射」
  变成编译错误（已实测：往 union 里加一个假 kind，`tsc -b` 直接报缺失属性）。
2. **`unknown` 故意不在表里**：兜底路径能从 `status` 挤出 `APP-418` 这类更具体的码，静态写一条
   `APP-000` 反而丢信息，所以类型用 `Exclude<…, "unknown">`。

## 6. 并行会话与 worktree 约定（本模块）

- 每个批次一个 worktree，基线永远取最新 `origin/main`（禁止从别的 feature 分支派生）。
- 一个 PR 只承载一个任务；迁移链、测试分片清单不做手工合并（分片用
  `python3 scripts/ci/build-test-shards.py --shards 4` 重生成，Windows 产物要转 LF）。
- **跑 `run-pytest-shards.sh` 前先确认 `python3` 不是 Microsoft Store 存根**（Windows 本机
  退出码 49、无输出）。该脚本的 fail-closed 覆盖守卫调 `python3` 做分片覆盖检查，存根会让它
  **静默失败**并报成「清单没有覆盖全部测试文件」——看着像分片清单过期，其实是没跑起来。
  用 POSIX 路径垫一个 shim 并 `hash -r`：`export PATH="/tmp/pyshim:$PATH"`（`$CLAUDE_JOB_DIR`
  之类是 Windows 反斜杠路径，直接拼进 PATH 不生效）。2026-09-16 与 2026-09-22 各踩一次。
- 改动客户泳道样式只写 `client/src/customer/*.css`（手写文件），不要写进 `styles.css`——那会被
  `scripts/split_customer_styles.mjs` 复制进生成的 `customer-access.css` 造成重复定义。
- 客户包不得混入 `admin-*` 样式（`client/src/entryContract.test.ts` 与 `scripts/verify_customer_bundle.mjs`
  会卡），所以客户侧确认框另建 `CustomerConfirmDialog`，不复用管理端组件。
